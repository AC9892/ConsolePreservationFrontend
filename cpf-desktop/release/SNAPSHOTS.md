# Automatic snapshot history

CPF keeps the three newest automatic snapshots in each category: NAND, firmware, and SD. Retention runs before boot and after a successful shutdown. A running session may temporarily create one additional snapshot.

Only files with the worker's generated names are eligible: `before-runtime-<token>.bin`, `libretro-<token>.bin`, `before-rebase-<token>.bin`, and SD `runtime-before-<token>/dsi_sd_card.bin`. Tokens must match the numeric or UUID format generated by CPF. Manually named snapshots, save backups, captures, original dumps, and current working storage are excluded. Linked directories and junctions are not traversed. SD snapshot directories containing additional files are left alone.

Existing automatic history is trimmed on the next boot of the updated worker. Each removal is recorded as `SNAPSHOT_PRUNED` in `logs/events.jsonl`, with the path, byte count, and rollback availability. Earlier modification records retain their hashes; a later pruning event means that snapshot can no longer reverse the change.

Snapshots are still complete copies. This change bounds automatic history; changed-block snapshots and compression are not implemented. SD storage use depends on the size of its image, rather than a fixed byte budget.

This source change requires an updated `DSi Backend.exe`. Previously downloaded release ZIPs are unchanged.
